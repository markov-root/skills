## 1. Anthropic / Claude Code

Claude prompt caching is prefix-based: the provider reuses the start of the request up to a cache breakpoint, and a change anywhere in that prefix changes the cache key for everything after it [Anthropic API prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching). Claude Code structures requests as stable system prompt, project context, then growing conversation so ordinary turns append rather than rewrite earlier context [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching). Claude Code manages caching automatically unless disabled [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching).

| Field                                    | Value for agent builders                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cache write cost multiplier              | 5-minute TTL: `1.25x` base input; 1-hour TTL: `2x` base input [Anthropic API prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| Cache read cost multiplier               | `0.1x` base input [Anthropic API prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| Cache TTL / lifetime                     | Default API TTL is 5 minutes, refreshed on cache use; optional 1-hour TTL costs more [Anthropic API prompt caching](https://platform.claude.com/docs/en/build-with-claude/prompt-caching). Claude Code uses 1-hour TTL automatically on Claude subscriptions, but defaults to 5 minutes for API keys and third-party providers unless `ENABLE_PROMPT_CACHING_1H=1` is set [Claude Code cache lifetime](https://code.claude.com/docs/en/prompt-caching#cache-lifetime).                                                                                                                                                                                                                                                                                                                                                       |
| Minimum cacheable prefix size            | Model-dependent: 512 tokens for Claude Opus 5 / Fable 5 / Mythos 5; 1,024 tokens for Claude Sonnet 5, Sonnet 4.6/4.5, Opus 4.8, Opus 4.1/4; 2,048 or 4,096 for other listed legacy/current models [Anthropic cache limitations](https://platform.claude.com/docs/en/build-with-claude/prompt-caching).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| Exact actions that invalidate cache      | Claude Code documents these invalidators: switching models; changing effort level; first enablement of fast mode; connecting/disconnecting an MCP server when its tools are loaded into the prefix; enabling/disabling a plugin that changes prefix-loaded MCP tools; denying an entire built-in tool by bare tool name such as `Bash` or `WebFetch`; `/compact`; upgrading Claude Code or resuming a long session after upgrade [Claude Code invalidation list](https://code.claude.com/docs/en/prompt-caching#actions-that-invalidate-the-cache). At the API level, changing any block at or before a cache breakpoint changes the prefix hash; changes to `tool_choice` or image presence also invalidate cache [Anthropic API invalidation notes](https://platform.claude.com/docs/en/build-with-claude/prompt-caching). |
| Actions that do **not** invalidate cache | Repository file edits append file-change notices rather than rewriting earlier file reads; editing root/user `CLAUDE.md` mid-session does not apply until `/clear`, `/compact`, or restart; changing permission mode is cache-safe except `opusplan` model switches; skills and commands append instructions; `/recap` appends output; `/rewind` truncates to an earlier cached prefix [Claude Code cache-safe actions](https://code.claude.com/docs/en/prompt-caching).                                                                                                                                                                                                                                                                                                                                                     |
| Usage fields reporting hits/writes       | `usage.cache_creation_input_tokens` for writes and `usage.cache_read_input_tokens` for reads; total input is `cache_read_input_tokens + cache_creation_input_tokens + input_tokens` [Anthropic usage fields](https://platform.claude.com/docs/en/build-with-claude/prompt-caching). Claude Code statusline uses the same fields in `current_usage` [Claude Code cache performance](https://code.claude.com/docs/en/prompt-caching#check-cache-performance).                                                                                                                                                                                                                                                                                                                                                                  |

**Agent design implications.** Treat the system prompt, tool schema set, output style, model, effort level, working directory snapshot, and project-root `CLAUDE.md` as session-start invariants [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching). Anthropic’s own Claude Code engineering guidance is blunt: static content first, dynamic content last; do not change tools or models mid-session; use messages for updates; defer tools rather than removing them; make forks share the parent prefix [Anthropic Claude Code caching lessons](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything). For compaction, use the same system prompt, tool definitions, user context, and message prefix as the parent, then append the compaction instruction, otherwise the summarization call pays full uncached input [Anthropic Claude Code caching lessons](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything).

## 2. OpenAI / Codex / GPT-5.x

OpenAI prompt caching is automatic for eligible requests and reuses exact prompt prefixes; static instructions/examples should be placed first, while variable user-specific content should be placed last [OpenAI prompt caching guide](https://developers.openai.com/api/docs/guides/prompt-caching). The API field is `cached_tokens`, not `cached_input_tokens`; product and pricing pages may call the billing category “cached input” [OpenAI prompt caching guide](https://developers.openai.com/api/docs/guides/prompt-caching), [GPT-5.1-Codex model page](https://developers.openai.com/api/docs/models/gpt-5.1-codex).

| Field                                       | Value for agent builders                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cache write cost multiplier                 | GPT-5.6 and later: `1.25x` uncached input rate and reported as `cache_write_tokens`; before GPT-5.6, cache writes have no additional fee [OpenAI prompt caching guide](https://developers.openai.com/api/docs/guides/prompt-caching).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| Cache read cost multiplier                  | For current GPT-5.x/Codex pricing shown in model pages, cached input is `0.1x` input, e.g. GPT-5.1-Codex `$1.25` input vs `$0.125` cached input per 1M tokens [GPT-5.1-Codex model page](https://developers.openai.com/api/docs/models/gpt-5.1-codex). GPT-5.6 comparison pages also show cached input at `0.1x` input [OpenAI model comparison](https://developers.openai.com/api/docs/models/compare).                                                                                                                                                                                                                                                                                                                                                                                                      |
| Cache TTL / lifetime                        | GPT-5.6 and later: `prompt_cache_options.ttl` currently supports only `30m`, which is also the default minimum lifetime [OpenAI prompt cache retention](https://developers.openai.com/api/docs/guides/prompt-caching). Earlier GPT-5.x models: `prompt_cache_retention: "in_memory"` generally lasts 5-10 minutes of inactivity, up to 1 hour; `prompt_cache_retention: "24h"` is supported on listed models including `gpt-5.1-codex`, `gpt-5.1-codex-mini`, `gpt-5.1-codex-max`, `gpt-5-codex`, and `gpt-5` [OpenAI prompt cache retention](https://developers.openai.com/api/docs/guides/prompt-caching).                                                                                                                                                                                                  |
| Minimum cacheable prefix size               | 1,024 tokens; all requests expose `cached_tokens`, but under-threshold requests report zero [OpenAI requirements](https://developers.openai.com/api/docs/guides/prompt-caching).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Exact actions that invalidate or miss cache | OpenAI documents exact prefix matching: any change in the cacheable prefix can miss; tools and images must be identical between requests; image `detail` affects tokenization; for explicit breakpoints, content after the breakpoint can change without invalidating the earlier prefix [OpenAI prompt caching guide](https://developers.openai.com/api/docs/guides/prompt-caching). On GPT-5.6+, reliable matching requires a stable `prompt_cache_key`; using a different key changes routing/matching behavior, so keep a stable key per shared prefix [OpenAI prompt cache key](https://developers.openai.com/api/docs/guides/prompt-caching). Expiry or eviction also causes misses; manual cache clearing is not available [OpenAI FAQ](https://developers.openai.com/api/docs/guides/prompt-caching). |
| Usage fields reporting hits/writes          | Responses API: `usage.input_tokens_details.cached_tokens`; Chat Completions: `usage.prompt_tokens_details.cached_tokens`; GPT-5.6+ also reports writes as `cache_write_tokens` [OpenAI usage fields](https://developers.openai.com/api/docs/guides/prompt-caching).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |

**Agent design implications.** For Codex-like agents using Responses API, preserve and resend previous user inputs and every response output item when managing history manually; this is especially important for reasoning continuity and cache efficiency in GPT-5.6 model guidance [OpenAI model guidance](https://developers.openai.com/api/docs/guides/latest-model). On GPT-5.6+, use `prompt_cache_options.mode: "explicit"` when implicit caching would write fast-changing conversation tails and create unnecessary write charges; explicit mode uses only your breakpoints and avoids cache writes if no breakpoint exists [OpenAI prompt cache breakpoints](https://developers.openai.com/api/docs/guides/prompt-caching). For high-volume shared-prefix workloads, partition `prompt_cache_key` values so each key remains around the documented 15 RPM guidance, while preserving a stable key-to-prefix mapping [OpenAI prompt cache key](https://developers.openai.com/api/docs/guides/prompt-caching).

## 3. Google / Gemini

Gemini offers implicit caching and explicit context caching. Implicit caching is enabled by default for Gemini 2.5 and newer models, but cost savings are not guaranteed; explicit caching creates a `CachedContent` resource and gives predictable reuse at the cost of cache management [Gemini context caching](https://ai.google.dev/gemini-api/docs/generate-content/caching?hl=en).

| Field                                       | Value for agent builders                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Cache write cost multiplier                 | Gemini Developer API docs do not express explicit cache creation as an Anthropic/OpenAI-style “write multiplier”; billing is based on cached token count, storage duration/TTL, and normal non-cached input/output charges [Gemini explicit caching costs](https://ai.google.dev/gemini-api/docs/generate-content/caching?hl=en). Current Developer API pricing shows context-caching token prices plus token-hour storage, e.g. Gemini 3.6 Flash input `$1.50` vs context caching `$0.15` plus `$1.00 / 1M tokens/hour`, implying `0.1x` cached-token pricing for that model [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing).                                                                                                             |
| Cache read cost multiplier                  | Model/pricing-tier-specific. Current Gemini Developer API pricing often shows context caching at `0.1x` input, e.g. Gemini 3.6 Flash `$0.15` vs `$1.50`; Gemini 2.5 Flash `$0.03` vs `$0.30`; Gemini 3.1 Flash-Lite `$0.025` vs `$0.25` for text/image/video [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing).                                                                                                                                                                                                                                                                                                                                                                                                                              |
| Cache TTL / lifetime                        | Explicit cache TTL defaults to 1 hour if unset and can be set by `ttl` or `expire_time`; docs state no minimum or maximum TTL bounds for explicit caching [Gemini context caching](https://ai.google.dev/gemini-api/docs/generate-content/caching?hl=en). API cache resources expose `ttl` and `expireTime`, and only TTL/expiry can be updated after creation [Gemini caching API](https://ai.google.dev/api/caching). Implicit in-memory caching is project-isolated RAM with a 24-hour TTL according to Gemini ZDR docs [Gemini ZDR docs](https://ai.google.dev/gemini-api/docs/zdr?hl=en).                                                                                                                                                             |
| Minimum cacheable prefix size               | Implicit caching minimums in the current guide: Gemini 3.5 Flash 4,096; Gemini 3.1 Pro Preview 4,096; Gemini 2.5 Flash 2,048; Gemini 2.5 Pro 2,048 [Gemini implicit caching](https://ai.google.dev/gemini-api/docs/generate-content/caching?hl=en). The guide also says minimums vary by model and max cache size equals the model max [Gemini additional considerations](https://ai.google.dev/gemini-api/docs/generate-content/caching?hl=en).                                                                                                                                                                                                                                                                                                           |
| Exact actions that invalidate or miss cache | Implicit: Google documents only heuristics, not an exhaustive invalidation list; cache hits require similar prefixes sent close together, so changing the large/common prefix or waiting beyond cache lifetime can miss [Gemini implicit caching](https://ai.google.dev/gemini-api/docs/generate-content/caching?hl=en). Explicit: `contents`, `tools`, `model`, `systemInstruction`, `displayName`, and `toolConfig` are immutable; changing any of those requires a new cache resource, and cached content can be used only with the model it was created for [Gemini caching API](https://ai.google.dev/api/caching). Deleting a cache, expiry, or using a different cache name prevents reuse [Gemini caching API](https://ai.google.dev/api/caching). |
| Usage fields reporting hits/writes          | GenerateContent returns cache-hit token counts in `usage_metadata`; cache create/get/list operations return cached content metadata and usage metadata [Gemini context caching](https://ai.google.dev/gemini-api/docs/generate-content/caching?hl=en). The cache resource’s `usageMetadata.totalTokenCount` reports how many tokens the cached content consumes [Gemini caching API](https://ai.google.dev/api/caching).                                                                                                                                                                                                                                                                                                                                   |

**Agent design implications.** For implicit caching, put large common repo summaries, tool instructions, and invariant build/test policy first, then append current task details near the end [Gemini implicit caching](https://ai.google.dev/gemini-api/docs/generate-content/caching?hl=en). For explicit caching, model a repo snapshot or large document bundle as a `CachedContent` object; store the cache name in session state and treat it as immutable except TTL/expiry updates [Gemini caching API](https://ai.google.dev/api/caching). Do not use explicit context caching when an absolute zero-data footprint is required, because the cached context itself persists until its `ttl` or `expire_time` [Gemini ZDR docs](https://ai.google.dev/gemini-api/docs/zdr?hl=en).

## 4. OpenRouter

OpenRouter passes provider-side prompt caching through to upstream providers and adds sticky routing to improve cache-hit probability [OpenRouter prompt caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching). This is separate from OpenRouter response caching, which caches entire identical responses at the router layer [OpenRouter response caching](https://openrouter.ai/docs/guides/features/response-caching).

| Field                                       | Value for agent builders                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Cache write cost multiplier                 | Upstream-dependent. OpenRouter documents Anthropic writes as `1.25x` for 5-minute TTL and `2x` for 1-hour TTL; Alibaba/Qwen explicit writes as `1.25x`; DeepSeek writes at `1.0x`; OpenAI writes as no cost in the OpenRouter guide, though OpenAI’s own current GPT-5.6+ docs bill writes at `1.25x`, so treat OpenAI’s official docs as authoritative for GPT-5.6+ [OpenRouter prompt caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching), [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching).                                                                                                                                                                                                                                                                                                                                                                                  |
| Cache read cost multiplier                  | Upstream-dependent. OpenRouter documents Anthropic `0.1x`, DeepSeek `0.1x`, Alibaba/Qwen `0.1x`, Grok `0.25x`, Groq `0.5x`, OpenAI `0.25x` or `0.5x` depending on model, and Gemini cached tokens at `0.25x` in its router guide [OpenRouter prompt caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching). Because upstream pricing changes, reconcile against provider docs for each routed model.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| Cache TTL / lifetime                        | Upstream-dependent. OpenRouter exposes Anthropic `cache_control` 5-minute default and optional `ttl: "1h"`; Gemini-on-OpenRouter cache writes are documented as 5-minute TTL that does not update; OpenAI uses its own automatic provider caching [OpenRouter prompt caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| Minimum cacheable prefix size               | Upstream-dependent. OpenRouter documents OpenAI minimum 1,024 tokens; Anthropic per-model minimums; Gemini-on-OpenRouter minimums of 1,024 for Gemini 2.5 Flash and 4,096 for Gemini 2.5 Pro, though Google’s own current Developer API guide lists 2,048 for Gemini 2.5 Flash/Pro and 4,096 for Gemini 3.5 Flash / 3.1 Pro Preview [OpenRouter prompt caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching), [Gemini implicit caching](https://ai.google.dev/gemini-api/docs/generate-content/caching?hl=en).                                                                                                                                                                                                                                                                                                                                                                                                         |
| Exact actions that invalidate or miss cache | All upstream provider invalidators still apply. OpenRouter-specific miss risks: manual `provider.order` disables sticky routing; without `session_id`, stickiness is derived from the first system/developer message and first non-system message, so changing those can route the conversation differently; provider fallback can move traffic to a different provider endpoint; router models can otherwise resolve to a different model unless session stickiness pins the resolved model [OpenRouter prompt caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching). For Gemini through OpenRouter, only the final `cache_control` breakpoint is used for normal message content, and dynamic content should be moved out of the first system/developer message because Gemini treats `systemInstruction` as immutable [OpenRouter Gemini caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching). |
| Usage fields reporting hits/writes          | `usage.prompt_tokens_details.cached_tokens` for reads and `usage.prompt_tokens_details.cache_write_tokens` for writes; `cache_discount` on generation details reports dollar savings/extra write cost [OpenRouter prompt caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                        |

**Agent design implications.** Always send a stable `session_id` for multi-turn agent work so provider stickiness starts before OpenRouter observes a cache hit [OpenRouter prompt caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching). Avoid manual provider ordering unless determinism of vendor choice is more important than sticky cache routing [OpenRouter prompt caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching). If you target multiple upstreams, use Anthropic-style `cache_control` breakpoints only where the upstream/OpenRouter mapping supports them, and test `cached_tokens` / `cache_write_tokens` per selected model [OpenRouter prompt caching](https://openrouter.ai/docs/guides/best-practices/prompt-caching).

## A. Actionable Cache Rules

1. Keep the stable prefix byte-for-byte stable: system/developer instructions, tool schemas, structured-output schemas, images/files, and large repo context should be ordered first and should not be rewritten mid-session [Anthropic lessons](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything), [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching), [Gemini implicit caching](https://ai.google.dev/gemini-api/docs/generate-content/caching?hl=en).

2. Append dynamic state instead of editing earlier prompt layers. File-change notices, timestamps, mode changes, and task updates should be added as later messages when the provider allows it; editing the system prompt or prefix forces recomputation after the edit [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching), [Anthropic lessons](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything).

3. Do not change model, reasoning/effort tier, or speed headers deep in a long session unless the cache rebuild is intentional. Claude Code keys cache by model and effort, and fast-mode enablement is part of the cache key [Claude Code invalidation](https://code.claude.com/docs/en/prompt-caching#actions-that-invalidate-the-cache). OpenAI and Gemini cache resources are also model-specific in practice; Gemini explicitly says cached content can only be used with the model it was created for [Gemini caching API](https://ai.google.dev/api/caching).

4. Do not add/remove prefix-loaded tools mid-session. Tool definitions are part of Anthropic and OpenAI cacheable prompt material, so changing the tool set changes the cacheable prefix [Claude Code MCP invalidation](https://code.claude.com/docs/en/prompt-caching#actions-that-invalidate-the-cache), [OpenAI cacheable content](https://developers.openai.com/api/docs/guides/prompt-caching). Prefer deferred tool loading, stable stubs, or mode tools such as “enter plan mode” over swapping schemas [Anthropic lessons](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything).

5. Put cache breakpoints immediately after stable bulk content, not after timestamps, user questions, or other per-turn content. Anthropic writes only at breakpoints and does not magically cache stable content behind a changing breakpoint [Anthropic breakpoint mechanics](https://platform.claude.com/docs/en/build-with-claude/prompt-caching); OpenAI explicit breakpoints similarly protect only content before the breakpoint [OpenAI breakpoints](https://developers.openai.com/api/docs/guides/prompt-caching).

6. For GPT-5.6+, use explicit breakpoints when implicit caching would write too much churn. Cache writes cost `1.25x`, so log `cache_write_tokens` vs later `cached_tokens` and move/remove breakpoints that do not earn back their write cost [OpenAI prompt caching](https://developers.openai.com/api/docs/guides/prompt-caching).

7. Prewarm only with the same effective prompt/rendering configuration as production requests. Anthropic warns that different thinking/effort configuration can write a cache entry real traffic never hits [Anthropic prewarming](https://platform.claude.com/docs/en/build-with-claude/prompt-caching).

8. Compact at task boundaries, not in the middle of an active edit/debug loop. Claude Code says `/compact` replaces history with a summary and invalidates the conversation layer, while system/project context can remain cached if unchanged [Claude Code compaction](https://code.claude.com/docs/en/prompt-caching#actions-that-invalidate-the-cache).

9. For forks, subagents, and summarizers, preserve the parent prefix. Anthropic’s Claude Code compaction uses the same parent system prompt, context, tools, and message history, then appends the summary request so the expensive long prefix is cache-read [Anthropic lessons](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything).

10. Route consistently. Use OpenAI `prompt_cache_key` for high-volume shared-prefix workloads [OpenAI prompt cache key](https://developers.openai.com/api/docs/guides/prompt-caching), and use OpenRouter `session_id` for multi-turn agent sessions so provider stickiness is explicit [OpenRouter sticky routing](https://openrouter.ai/docs/guides/best-practices/prompt-caching).

## B. Usage-Level Suggestions

| Context remaining | Agent behavior                                                   | Cache-aware advice                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| ----------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| ~70% remaining    | Continue normal work, but start budget telemetry.                | Log read/write fields every turn: Anthropic `cache_read_input_tokens` / `cache_creation_input_tokens`; OpenAI/OpenRouter `cached_tokens` / `cache_write_tokens`; Gemini `usage_metadata` [Anthropic usage](https://platform.claude.com/docs/en/build-with-claude/prompt-caching), [OpenAI usage](https://developers.openai.com/api/docs/guides/prompt-caching), [OpenRouter usage](https://openrouter.ai/docs/guides/best-practices/prompt-caching), [Gemini usage](https://ai.google.dev/gemini-api/docs/generate-content/caching?hl=en). |
| ~50% remaining    | Reduce new context growth.                                       | Prefer targeted file reads, concise tool outputs, and durable summaries appended after the cached prefix. Do not switch model/effort or reload prefix tools unless the next phase truly needs it [Claude Code invalidation](https://code.claude.com/docs/en/prompt-caching#actions-that-invalidate-the-cache).                                                                                                                                                                                                                             |
| ~30% remaining    | Prepare compaction before the provider forces it.                | Summarize at a natural boundary; preserve stable instructions in root context, and ensure compaction/fork requests reuse the parent prefix [Claude Code context window](https://code.claude.com/docs/en/context-window), [Anthropic lessons](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything).                                                                                                                                                                                                      |
| <20% remaining    | Avoid exploratory bulk reads unless needed for the final answer. | Either finish the current narrow task or compact with a cache-safe parent-prefix fork; avoid starting a new tool-heavy investigation that will immediately be summarized away [Claude Code context window](https://code.claude.com/docs/en/context-window).                                                                                                                                                                                                                                                                                |

Durable rules worth baking into a global `CLAUDE.md`:

- Keep stable instructions stable; append task updates rather than rewriting loaded context [Claude Code prompt caching](https://code.claude.com/docs/en/prompt-caching).
- Do not switch model, effort, speed mode, or prefix-loaded tools mid-task unless the user explicitly accepts the cache/cost hit [Claude Code invalidation](https://code.claude.com/docs/en/prompt-caching#actions-that-invalidate-the-cache).
- Read only the files needed for the current step; large repository sweeps should be summarized deliberately and reused, not repeated.
- Run compaction at task boundaries and preserve the current objective, decisions, file paths touched, test status, and unresolved risks [Claude Code context window](https://code.claude.com/docs/en/context-window).
- Monitor cache hit fields as first-class telemetry, and treat sudden drops in cached tokens as a regression in the agent harness [Anthropic lessons](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything).
